# T09 — Carga web por vista (11/11/2026)

## Alcance

Se inspeccionó la compilación actual y la entrega de archivos de Fastify antes de cambiar código. El JS inicial era un solo archivo de 599,87 kB (158,44 kB gzip). El servidor aplicaba `Cache-Control: no-store` a todos los recursos, incluidos los archivos estáticos versionados.

Se separaron las vistas grandes de público y administración mediante imports dinámicos. La lista inicial de organizaciones, los controles pequeños y la captura de partido conservan carga directa. El servidor permite reutilizar durante un año solamente JS/CSS con hash en su nombre y evita consultar la sesión al servir archivos estáticos; HTML, API, sesión y service worker no pasan a caché pública. La pantalla diferida muestra carga breve y, si falla, un botón para recargar.

## Medición y verificación local

- `npm run build`: JS inicial en `index` y `runtime-core`: 388,53 + 59,32 = **447,85 kB** (101,99 + 23,30 = **125,29 kB gzip**). Reducción aproximada del 25 % sin comprimir y 21 % con gzip frente al JS inicial anterior. Las vistas diferidas se descargan cuando se visitan; la Copa pública por posiciones añade 17,57 kB de JS y 8,67 kB de CSS, antes de comprimir.
- `npm run typecheck`: correcto.
- `npm test`: 93/93 correctas después de la partición, el ajuste de caché y la omisión de sesión para archivos estáticos. La prueba de recursos públicos comprueba que un archivo con hash recibe caché inmutable y uno sin hash no la recibe.
- Inyección directa al servidor real: `/assets/index-D6hPT7Wq.js` respondió 200 con `Cache-Control: public, max-age=31536000, immutable`. La consulta independiente de `/index.html` no pudo acceder a PostgreSQL por `EACCES` de la consola restringida; la navegación en el servidor local y las pruebas de integración sí cargaron la web.
- Navegador local: la portada abrió la Federación Caacupeña y la Copa Caacupé con partidos por jornada; la sesión administrativa abrió la lista de torneos, Pagos y Clasificación tras la carga diferida. No se editó ningún dato.

## Límites

Estas cifras son tamaño de salida de Vite, no tiempos de red. No se probó aún en teléfono físico ni con red móvil inestable. La PWA almacena los recursos diferidos al visitarlos bajo un service worker activo; una vista nunca abierta puede requerir red en el primer acceso.
